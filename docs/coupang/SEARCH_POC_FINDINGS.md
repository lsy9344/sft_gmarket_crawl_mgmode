## 판명된 사실 (누적)

1. **검색 결과는 키워드당 ~73개 상한.** 무한 스크롤도, 페이지네이션도 없음.
   결과 이후는 전부 추천/광고 모듈. 이것이 신형 SRP의 설계 상한.
2. **확장 경로는 연관 검색어뿐.** 사이드바 연관어 각 ~8개 → 각각 독립 검색.
   연관어의 연관어로 2차 확장도 가능(단, 요청량·중복 관리 필요).
3. **직접 URL page≥2는 빈 셸 방어.** 검색은 반드시 검색창 타이핑 경로로.
4. **소프트 차단은 일시적** — 12시간 쿨다운으로 해제 확인. 영구 블랙리스트 아님.
5. **차단 임계 근사**: 20분 내 6세션 → 차단. 30~60분 간격 단일 세션은 문제없었음.
6. 신형 차단 페이지 키워드: **"사용권한"** (기존 감지 목록에 추가 완료).
7. 카테고리 링크(`/np/categories/{id}`)가 사이드바에 노출됨 —
   카테고리 페이지 페이지네이션 동작 여부는 미검증(차후 과제).

## 운영 파라미터 (rev.2 확정)

| 항목 | 값 | 근거 |
|------|-----|------|
| 세션 간격 | ≥ 30분 (권장 60분) | 20분 6세션 차단 / 30분+ 간격 무사고 |
| 세션당 검색 수 | ≤ 2~3개 키워드 | 세션당 체류 행위량 제한 |
| 일일 세션 수 | ≤ 3~5 | 보수적 초안, 추가 실측 가능 |
| 키워드 1개당 기대 수집량 | ~73개 (연관어 확장 시 ×N) | 실측 |
| 차단 감지 시 | 즉시 중단 + 최소 수시간 쿨다운 | rev.1→rev.2로 해제 확인 |

## 제품 설계 영향

- **"키워드의 상품 모두"의 재정의 필요**: 쿠팡 신형 검색은 키워드당 ~73개만 노출.
  "모두" = (a) 키워드당 상위 73개, 또는 (b) 연관 검색어 확장으로 도달 가능한 전체.
  사용자 결정 필요.
- 엔진 구조: 검색창 타이핑 → 결과 수집 → 사이드바 연관어 추출 →
  다음 키워드는 새 세션(30분+ 간격)에서 같은 흐름.
- 파싱: 신형 React SRP, 클래스명 해시됨 → `a[href*="/vp/products/"]` 기준 추출,
  상품ID/itemId/vendorItemId는 href 쿼리에 포함됨(기존 스키마 호환).

## 남은 과제 (다음 실측)

1. `/np/categories/{id}?page=N` 카테고리 페이지네이션 동작 여부
   (검색 외 대량 수집 경로 후보)
2. 연관어 2차 확장의 중복률 측정
3. 딜레이 스윕(poc4 --sweep) — 오늘 세션량 소진으로 연기
