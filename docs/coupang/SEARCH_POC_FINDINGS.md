# Coupang 검색 크롤링 PoC 실측 결과 (rev.1)

> 작성일: 2026-08-13 · 워크트리: `coupang-search`
> 목적: `/np/search` 키워드 검색 크롤링 타당성 실측

## 한 줄 요약

**직접 URL 접근은 1페이지만 SSR됨. 검색창 경로(타이핑→Enter)는 성공했으나,
단시간 반복 세션(20분에 6회)에서 소프트 차단(403 '사용권한') 발생.
차단 없이 쓰려면 세션 간격·일일 횟수 제한이 필수다.**

## 실측 결과 (2026-08-13, 주거용 1 IP, Camoufox headed + geoip)

| # | 시도 | 결과 |
|---|------|------|
| 1 | 직접 URL `?q=...&page=1` | ✅ SSR 2.3MB, 상품 82개 |
| 1 | 직접 URL `?page=2,3` | ⚠️ 차단 아님, 그러나 128KB 빈 셸 (상품 0) |
| 2 | 직접 URL page 1~5 | ✅ 전부 200, page1만 86개, 2~5는 빈 셸 |
| 3 | 검색창 타이핑 → Enter | ✅ 68개 로드 → 스크롤로 87개까지 증가 |
| 3 | 이어서 스크롤 | ❌ 87개에서 정체 (4회 연속 증가 없음) |
| 4 | 검색창 타이핑 → Enter | ❌ 3KB **403 '사용권한' 페이지** (소프트 차단) |
| 5 | 검색창 타이핑 → Enter (폴링 추가) | ❌ 동일 403 |

## 판명된 사실

1. **`/np/search` page≥2 직접 URL 접근은 서버가 렌더링을 거부한다.**
   차단(403)이 아니라 빈 셸(128KB)을 돌려줌 — 봇에게 "성공처럼" 보이는
   형태의 방어. 페이지네이션은 검색창 경로 + 상호작용 통해서만 가능.

2. **검색창 타이핑 → Enter 경로는 실제로 동작한다.**
   신형 SRP(React, 해시된 클래스명)가 약 60~87개를 SSR/하이드레이션으로 제공.

3. **스크롤로는 87개 이상 늘지 않았다.** 무한 스크롤이 아니라
   하단 페이지네이션(`a.move.next`) 기반일 가능성. 아직 클릭 검증 미완료.

4. **단시간 반복이 소프트 차단을 유발했다.** 20분 내 6개 세션에서
   403 '사용권한' 페이지 등장. 키워드 미포함이라 기존 감지 로직이 놓침
   → `BLOCK_KEYWORDS`에 `"사용권한"` 추가 완료.

5. 차단 페이지에도 Akamai 센서 스크립트가 포함됨(점수 재수집용).
   이 상태에서 즉시 재시도하면 점수가 더 깎일 수 있음 → **쿨다운 필수**.

## 운영 파라미터 초안 (다음 실측으로 확정)

| 항목 | 초안 | 근거 |
|------|------|------|
| 세션 간격 | ≥ 30~60분 | 20분 6세션에서 차단 발생 |
| 세션당 검색 페이지 수 | ≤ 5 | 추가 실측 필요 |
| 일일 세션 수 | ≤ 3~5회 | 추가 실측 필요 |
| 키워드 전환 시 | 새 세션 권장 | 패턴 누적 회피 |

## 다음 단계

1. **쿨다운** (최소 수 시간~하루) 후 재실측 — 차단이 일시적인지 확인
2. 검색창 경로에서 하단 `a.move.next` 클릭 → page2+ 로드 여부 검증
3. 2가 되면: 페이지 전환 간 딜레이 스윕(10/20/30초)으로 한계 측정
4. 탭 설계: 검색창 경로 기반 엔진 + 차단 감지 시 즉시 중단/쿨다운 알림
