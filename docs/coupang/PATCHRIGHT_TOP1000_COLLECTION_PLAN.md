## 방법

쿠팡 카테고리 목록 페이지는 리뷰 수 정렬을 URL로 제공하지 않는다. 그래서
기존 Patchright 파이프라인과 같은 방식으로 목록 페이지를 순서대로 읽되,
카드 DOM에서 상품별로 리뷰 수 텍스트와 배송 표식(텍스트·로고 이미지)을 함께
추출해 파이썬에서 분류한다.

- 3P 카드만 저장하며, 카테고리별 중복(vendorItemId)은 제거한다.
- 카테고리당 3P 1,000개에 도달하면 해당 카테고리 확인을 마친다.
- 최종 파일 `top_1000_{카테고리ID}.csv`는 리뷰 수 내림차순으로 정렬하고
  동점은 수집 순서를 유지한다.
- 카테고리가 50페이지 안에 끝나지 않으면(빈 페이지 2회 연속 또는 3P
  1,000개 도달 전에 페이지 상한 도달) 그때까지 확인한 3P 상품 전체를
  정렬해 마친다. 식품 카테고리는 로켓 비중이 높아 1,000개 미만으로 끝날 수
  있으며 이 경우 실제 수집 수를 그대로 둔다.
- 카테고리 목록이 늘어나면 기존 진행 상태에서 완료된 카테고리는 그대로
  두고 남은 카테고리만 이어서 확인한다(상태 마이그레이션).

## 안전 규칙 (기존 봉투 그대로)

- 한 세션 최대 8페이지·상품 위치 480개이며 세션 중간에 카테고리를 넘지
  않는다.
- 실접속 사이 최소 60분을 지키고 예약은 80분 간격이다.
- 같은 감사 가능한 Chrome 프로필과 공통 안전 기록
  (`%LOCALAPPDATA%\SellerCollectorPatchrightCanary`)을 쓴다.
- `Access Denied`, Edgesuite 참조번호, CAPTCHA, HTTP 403/418/429 또는 한국어
  접근 제한 문구가 한 번이라도 보이면 안전 기록을 잠그고 예약 전체를 끈다.
- 오류로 0이 아닌 종료 코드가 나오면 실행기가 예약 작업을 즉시 비활성화한다.
- 정상 종료한 세션의 미사용 예약량만 안전 기록에 돌려놓는다.
- 쿠키 삭제, 새 프로필, 프록시, 무작위 행동 지연은 사용하지 않는다.
- Windows가 예약 시각에 꺼져 있으면 그 예약은 그냥 지나간다(몰아서 실행
  없음).

## 하위 카테고리 확장 예약 (2026-09-30 등록)

사용자 결정으로 17개 하위 카테고리를 이어서 확인한다. 작업명은 동일한
`PatchrightTop1000-80Min`을 다시 등록했고 한 번 실행마다 8페이지, 총 48회

일찍 끝나면 그만큼 짧아지고, 전체 수집이 끝나면 실행기가 남은 예약을 자동으로
끈다. 첫 실행은 2026-09-30 10:25, 간격은 80분, 마지막 예약은
2026-10-03 01:05다. 하위 카테고리는 대부분 1~3세션(8~19페이지) 안에 끝날
것으로 보며, 예약이 부족하면 이어서 추가 등록한다.

이어서 확인하는 카테고리는 땅콩/호두(194376)부터 트리 순서대로이며,
식용곤충(569073)이 마지막이다. 이미 끝낸 두 상위 카테고리의 기록과
데이터셋은 그대로 유지된다.
