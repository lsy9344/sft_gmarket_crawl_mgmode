## 계획 알고리즘 (§5 구현판)

물량을 알 때: S = 2N(스틸링 여유), G = 총물량/S. 물량 > 2G 인 카테고리는
페이지 조각(예상 페이지 = 물량/60, 조각 수 = 물량/G, 연속·서로소 구간),
나머지는 남은 예산(S − 조각 수)만큼의 bin 에 LPT packing. 설계 §5.1 의
`S = min(카테고리 수, 2N)` 은 whole 유닛에만 적용되는 phase-1 규칙이므로
물량 인지 경로에서는 카테고리 수 상한을 쓰지 않는다 — 그래야 §1 의
"카테고리 수 < 인스턴스 수여도 전 회선 활성"(§3.2 분할 천장 제거)이
성립한다. 물량 미지면 종전 라운드로빈 min(카테고리 수, 2N) 그대로.

판매자 조각 K: `clamp(ceil(상품 행 수 / seller_limit), 1, 인스턴스 수)`.
설계 §10 권장("인스턴스 수와 동일")에서 세션 1개 분량보다 작은 조각은
만들지 않게 변형 — 빈 조각은 즉시 완주하지만 폴더·큐가 부풀고 라운드
추적이 지저분해진다. 빈 조각도 브라우저 없이 즉시 완주하므로 안전.

## 배출 규칙 (§5.3)

완주 판정의 사실 근원은 디스크(조각 폴더의 `top_state.json`)다 — 실행 중
배출과 재시작 복원 배출이 같은 판정을 내고 멱등하다(이미 그 카테고리의
판매자 조각이 있으면 재배출 없음). 카테고리의 목록 전 조각 완료 → 상품
행 수 집계 → K개 판매자 조각을 대기 큐 끝에 추가 → 다음 도래한 아무
인스턴스나 승계. 복원 직후에도 스윕을 1회 돌아 죽기 직전 완주를 놓치지
않는다.

## 상태 호환 (§5.5)

`coupang_parallel_state.json` 에 `plan_version`(2)와 `units`(단위 사양,
배출된 판매자 조각 포함)이 추가됐다. 구버전 상태(version 1, plan_version
없음)를 새 계획으로 시작한 폴더에서 만나면 `root_family`(분할 모드 원본
가족)를 라운드로빈 재분할해 이전 규약(통짜 샤드)으로 재개한다 — 라운드로빈은
결정적이므로 같은 카테고리·샤드 수면 항상 같은 분할이 나온다. root_family
없이는 재구성 불가 → 새 배분 폴백(종전 동작). v1 상태 파일 형식 자체는
그대로라 구버전 코드도 읽을 수 있다.

## 검토 반영 (2026-10-07, 병합 전 코드 검토 4건)

1. **꼬리 병렬성 — 배출 시 종료 인스턴스 부활.** 인스턴스는 대기 큐가 빈
   순간 DONE 이 되는데, 판매자 조각은 목록 완료 시점(실행 후반)에 배출되므로
   다른 인스턴스 전원이 DONE 인 채 배출되면 마지막 한 인스턴스가 조각 전부를
   80분 간격으로 홀로 순차 처리했다 — §5.3 "어떤 회선도 굶지 않는다"가 런의
   끝자락에서 깨진다. `_sweep_emit_seller_units` 가 배출한 뒤
   `_revive_done_instances` 로 DONE 인스턴스를 WAITING(family_index=None,
   next_run_at=0)으로 되돌려 다음 run_due 에서 큐를 함께 승계받게 한다.
   차단/오류 인스턴스는 안전 장치 재심사 대상이라 부활시키지 않는다
   (재시작 시 `_restore_state` 가 다시 연다).
2. **목록 깊이 과소평가 절단 방지 — 끝 조각 개방.** 페이지 조각은 예상
   페이지(물량/60, 상한 50쪽)까지만 커버했는데, productCount 가 실제 목록
   깊이를 과소평가하면(페이지당 상품이 60보다 적은 경우) 마지막 조각이
   예상 종료에서 잘리고 그 뒤는 미수집이었다. 각 카테고리의 **마지막**
   조각만 전역 상한(MAX_CATEGORY_PAGES=50)까지 열어 실제 끝까지 추적하게
   했다 — 예상이 맞으면 빈 페이지 2회 관용(EMPTY_PAGE_TOLERANCE)이 예상
   종료 직후 조각을 완주시키므로 추가 비용은 빈 페이지 방문뿐이고 조각 간
   서로소성도 유지된다(끝 조각의 뒤쪽만 연장). 조각 정렬(무거운 것 먼저)은
   page_to 대신 구간 길이 기준으로 바꿔 연장이 순서를 왜곡하지 않게 했다.
   참고: TARGET_CATEGORY_ITEMS(1,000)은 조각별로 독립 적용되므로 통짜
   샤드 시절(카테고리당 1,000)보다 큰 카테고리를 더 깊이 수집할 수 있다
   — 데이터 품질에 유리, 트래픽은 증가 가능(의도된 변화).
3. **폴더 sid 승계 가드 — 타 인스턴스 회선 물려받기 차단.** 시작 sid 는
   폴더의 proxy_session_state.json 이 우선했는데, 조각/샤드 승계로 다른
   인스턴스가 쓰던 폴더를 물려받으면 그 회선(출구 IP)까지 승계해 두
   인스턴스가 같은 IP 를 공유하거나 프로필(쿠키)-IP 불일치가 생길 수
   있었다(2026-10-04 sid 충돌 사고와 같은 실패 유형). 폴더 sid 의
   네임스페이스(마지막 숫자 1자리를 뺀 접두사, i{N}_)가 호출자 인스턴스
   것과 같을 때만 승계하고, 아니면 자기 네임스페이스 sid 로 시작한다.
4. **배출 조각 카드 표기.** 배출된 판매자 조각은 시작 계획에 없어 카드
   표기가 기본 라벨로 떨어졌다. 매니저가 `units_appended` 이벤트(단위
   라벨)를 내보내고 워커 시그널 → 패널 `append_unit_names` 로
   `_family_names` 를 늘려 `WorkUnit.label` 표기가 유지된다.

검토에서 확인만 하고 변경하지 않은 것: 매니저 상태 파일
(coupang_parallel_state.json)이 삭제된 채 조각 폴더만 남으면 재계획이
폴더 상태와 어긋날 수 있다 — 종전 규약과 같은 취급으로 운영 매뉴얼에
"같은 폴더로 다시 시작" 규칙과 함께 상태 파일 삭제 금지를 명시했다.
