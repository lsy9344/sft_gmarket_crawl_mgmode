# Patchright 2026-09-03 일일 수집 일정

목표: 차단 회피 기능 없이 검증된 세션 봉투 안에서 하루 상품 한도 1,500개를 가능한
범위까지 사용한다.

## 근거

2026-09-02 확대 재검증은 다음과 같았다.

| 단계 | 간격 | 페이지 | 확인 상품 | 새 고유 상품 | 결과 |
|---|---:|---:|---:|---:|---|
| 1페이지 | - | 1 | 52 | 48 | HTTP 200 |
| 3페이지 | 3시간 5분 | 3 | 180 | 174 | HTTP 200 |
| 10페이지 | 3시간 5분 | 10 | 596 | 498 | HTTP 200 |

세 세션에서 상품 위치 828개, 새 고유 상품 720개를 저장했고 화면상 차단 신호는
없었다. 오늘 양이 작았던 주원인은 시간 간격보다 재검증 단계가 작게 시작했기
때문이다.

하루 세션이 3회로 제한된 상태에서는 간격만 줄여도 하루 수집량은 늘지 않는다.
간격과 총량을 동시에 바꾸면 다시 차단됐을 때 어느 변경이 원인인지 구분할 수 없다.
따라서 다음 날은 간격을 유지하고 하루 총량만 1,500개까지 사용한다.

## 예약

| 시각(KST) | 작업 | 목표 상품 |
|---|---|---:|
| 2026-09-03 00:10 | 현재 카테고리 최대 10페이지 | 최대 600개 |
| 2026-09-03 03:15 | 앞 단계 성공 시 최대 10페이지 | 최대 600개 |
| 2026-09-03 06:20 | 앞 단계 성공 시 남은 하루 한도 | 기본 300개, 최대 600개 |
| 2026-09-03 08:30 | 파일·차단·위치 오프라인 점검 | 0개 |

세션 사이에는 3시간 5분을 둔다. 세 번째 세션은 앞 세션에서 카테고리가 일찍 끝나
사용하지 않은 예약량이 있으면 남은 하루 한도 안에서 페이지 수를 늘린다. 한
세션의 최대 10페이지·600개와 카테고리 경계 금지는 그대로다.

## 중단 규칙

- 앞 단계가 실패·차단되면 뒤 단계는 브라우저를 열지 않는다.
- 차단·실패한 세션의 예약량은 되돌리지 않는다.
- 정상 종료한 세션에서 실제로 읽지 않은 상품 예약량만 되돌린다.
- 하루 최대 3세션·상품 위치 1,500개를 넘지 않는다.
- 쿠키 삭제, 새 프로필, 프록시, 무작위 행동 지연은 사용하지 않는다.
- Windows가 예약 시각에 꺼져 있거나 로그아웃 상태면 놓친 실접속을 몰아서 실행하지
  않는다.

## 시간 단축 판정

2026-09-03의 최대 1,500개 일정이 모두 HTTP 200이고 차단 신호가 없을 때만 다음
일정에서 간격 하나만 줄이는 시험을 검토한다. 첫 후보는 3시간 5분에서 2시간 35분
감축이다. 이 시험에서도 하루 3세션·1,500개는 유지한다.

시간 단축만으로 하루 수집량은 늘지 않는다. 실제 일일 총량을 1,500개보다 늘리는
결정은 별도 검증이며, 이번 일정에는 포함하지 않는다.

등록 뒤 08:30 오프라인 점검 작업을 같은 Windows 예약 환경에서 수동 실행해 종료
코드 0과 네트워크 이동 0회를 확인했다. 네트워크 없는 관련 테스트 60개와 코드
검사도 통과했다.
