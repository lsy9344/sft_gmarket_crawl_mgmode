# Coupang 로그인 Access Denied 사고 기록 (2026-08-31)

## 상태

- **현재 판정: 라이브 로그인·수집 중단(HOLD)**
- 개발 PC와 배포 PC는 서로 다른 지역·공유기를 사용했지만, 두 환경 모두
  Camoufox로 쿠팡 홈에 진입하는 단계에서 Akamai `Access Denied`가 발생했다.
- `docs/DEPLOYMENT_APPROVAL.md`의 중단 조건(명시적 차단)에 해당하므로,
  원인 분리와 별도 승인 전까지 라이브 자동 수집을 재개하지 않는다.

## 관찰된 사건

| 환경 | 시각(KST) | 관찰 결과 | Akamai Reference |
|---|---:|---|---|
| 개발 PC | 2026-08-31 19:14:39 | `http://www.coupang.com/` 접근 권한 없음 | `18.a5382017.1788171279.48af8604` |
| 배포 PC | 2026-08-31 19:21:53 | 동일한 `Access Denied`; 개발 PC와 다른 지역·공유기 | `18.1461ca17.1788171713.a441766` |

두 화면 모두 `errors.edgesuite.net` 링크를 제공했다. Reference 값은 오류 화면에
표시된 진단 식별자이며 인증정보가 아니다.

## 직전 로그인 흐름에서 확인된 문제

1. 최초 배포본은 폐기된 직접 로그인 주소를 열어 `찾을 수 없는 페이지`가
   표시됐다.
2. 오류 화면의 `쿠팡 홈으로`를 누르면 Camoufox의 기본 `newtab` 외에 다른
   페이지/창이 생겼다.
3. 앱은 처음 만든 한 페이지만 검사해, 사용자가 다른 페이지에서 정상 로그인해도
   최대 300초 동안 완료를 감지하지 못했다.
4. 사용자가 로그인 버튼을 여러 번 누르고 창을 열고 닫은 뒤 타임아웃과 취소가
   반복됐다.
5. 수정 방향은 기존 Camoufox 페이지 재사용, 쿠팡 홈에서 시작, 열린 모든 페이지의
   로그인 상태 확인이다. 단, 이 UI 수정만으로 Akamai 차단 문제가 해결됐다고
   판단하지 않는다.

## 런타임 확인

- 개발 PC의 GeoIP DB는 35일 경과로 사전검사에 실패했다.
- `CoupangRuntimeSetup.exe` 실행 후 GeoIP DB가 0일 상태로 갱신됐고 런타임
  검증은 통과했다.
- 갱신 뒤에도 개발 PC와 배포 PC에서 `Access Denied`가 발생했으므로, 이번
  차단을 단순 GeoIP DB 만료 문제로 설명할 수 없다.

## 현재 해석

### 확인된 사실

- 하나의 공유기·공인 IP에만 국한된 현상은 아니다.
- 로그인 API 제출 이전 또는 쿠팡 홈 진입 단계에서도 차단이 발생할 수 있다.
- 빌드·단위 테스트·런타임 검증 통과는 실제 Akamai 허용을 보장하지 않는다.
- Camoufox 로그인 버튼의 반복 실행은 현재 수집용 12시간 차단 게이트의 보호를
  받지 않는다.

### 아직 확인되지 않은 가설

- Camoufox/Firefox 계열의 브라우저·자동화 흔적이 공통 원인인지
- 짧은 시간의 반복 실행과 창 열기/닫기가 위험 점수를 높였는지
- 동일 계정, 쿠키, 기기 특성 또는 여러 신호의 조합이 영향을 줬는지
- 일반 Chrome은 허용되지만 Camoufox만 거부되는지

쿠팡의 실제 Akamai 규칙은 공개되지 않았으므로 위 항목을 확정 사실로 표현하지
않는다.

## 즉시 적용할 운영 규율

1. 두 PC 모두 Camoufox 로그인과 라이브 수집을 중단한다.
2. IP·지역·프로필을 바꿔가며 접근 제한을 회피하지 않는다.
3. 마지막 차단 시각 기준 최소 12시간 동안 재접속하지 않는다.
4. 반복 시도가 있었으므로 이번 사건은 24시간 보수적 대기를 적용한다.
   - 재검토 가능 시각: **2026-09-01 19:21:53 KST 이후**
5. 대기 시간이 지나도 자동 재시도하지 않는다. 먼저 배포 승인 상태와 사이트
   접근 정책을 재확인한다.
6. 다시 `Access Denied`, 403, 429 또는 CAPTCHA가 나오면 즉시 중단한다.

## 코드 보완 필요사항

- 로그인 페이지에서도 `Access Denied` 본문과 Akamai Reference를 감지한다.
- 로그인 중 차단을 감지하면 수집과 같은 영속 쿨다운 상태를 기록한다.
- 쿨다운 상태를 실행 파일 옆 출력 폴더가 아니라 Windows 사용자 기준 공용 위치에
  저장해, 앱 폴더를 바꿔도 게이트가 사라지지 않게 한다.
- 쿨다운 중에는 `쿠팡 로그인 (1회)` 버튼도 비활성화하고 해제 예정 시각을
  화면에 표시한다.
- Camoufox 실패 시 Patchright로 자동 폴백하지 않는다. 자동 폴백은 차단 직후
  요청을 하나 더 만드는 동작이기 때문이다.

## Patchright 검토 원칙

Patchright + 실제 Chrome은 Camoufox와 다른 브라우저 계열의 호환성 비교 후보일
수 있다. 그러나 차단 우회 수단으로 취급하거나 즉시 라이브 전환하지 않는다.

- 별도 승인과 사이트 정책 검토 없이 라이브 비교를 실행하지 않는다.
- 비교가 승인되더라도 한 PC·한 네트워크·한 영속 프로필에서 단 한 번의 홈 진입만
  수행한다.
- 일반 Chrome과 자동화 브라우저의 결과를 분리해 기록한다.
- 어느 단계에서든 거부 응답이 나오면 추가 브라우저로 재시도하지 않는다.

다음을 모두 충족하기 전에는 Coupang 로그인 수집을 재개하지 않는다.

- 로그인 차단 감지 및 영속 쿨다운 게이트 구현
- 정상 Chrome과 앱 브라우저의 최소 비교 계획 사전 승인
- 차단 해제 여부를 한 번의 요청으로 확인할 중단 기준 확정
- 결과와 Reference를 비밀정보 없이 기록할 로그 형식 확정
